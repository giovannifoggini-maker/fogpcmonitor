# FogMonitor by FogLabs

**Version 1.7.0** · A desktop system monitor for Windows 10/11 with a dark, rounded interface, subtle animations and mint-green accents.

FogMonitor reads available system metrics locally. The runtime uses only the Python standard library and Tkinter; no `pip` packages are required to run the source version.

## Languages

The interface supports **Italian and English**. Use the `UI` selector in the top-right corner to switch languages. Your preference is saved to the current user profile and restored the next time the app starts.

## Dashboard

- **CPU:** total usage, mini chart and up to 60 history samples.
- **RAM:** usage percentage, total, used and available memory.
- **GPU:** GPU-engine utilization when Windows and the driver expose the counter; otherwise it is marked unavailable.
- **System drive:** used percentage and free space.
- **Processes:** sort by name, PID or memory; search by process name or PID; double-click a row to copy its PID.
- **Smoother charts:** chart lines are redrawn when new samples arrive; animation moves only small endpoint indicators.
- **Controls:** pause/resume monitoring, manual refresh, 1/2/5-second sample interval and CSV export.
- **Privacy:** metrics remain local. FogMonitor has no account, login or telemetry.

## Run from source

Requirements: **Windows 10/11**, Python **3.10–3.13**, and Tkinter. External Python packages are not needed for normal use.

1. Extract the ZIP.
2. Double-click `Avvia-FogMonitor.bat`.
3. If the app does not start, run `Diagnostica-FogMonitor.bat`.

The error log is stored at `%LOCALAPPDATA%\FogLabs\FogMonitor\FogMonitor-error.log`. Language preference is stored in the same folder as `settings.json`.

## Build a portable Windows EXE

The source ZIP does not contain a precompiled executable. On Windows, install Python 3.13 with the Python Launcher and Tkinter, extract the project to a writable folder and run `Build-EXE.bat`. The script runs the tests, installs the build-only PyInstaller dependency, creates `dist\FogMonitor.exe`, and packages it as `release\FogMonitor-by-FogLabs-Windows.zip`. The target PC does not need Python to run that EXE. The first build requires an internet connection to download PyInstaller.

## Publish with GitHub Actions

The repository includes `.github/workflows/windows-release.yml`. Upload the project to a GitHub repository, then run **Actions → Build Windows release**, or push a tag beginning with `v` (for example, `v1.7.0`). The workflow builds on a Windows runner and uploads the portable ZIP as an artifact; tags also create a GitHub Release attachment.

## Accuracy and limitations

- CPU, memory and drive values come from Windows APIs.
- GPU data depends on the Windows performance counter and the installed graphics driver.
- Generic Windows APIs do not expose reliable CPU/GPU temperatures, so the app does not invent them.
- Protected processes may not expose their name or memory usage.
- The source package and UI smoke tests can be checked on this development environment, but the Windows EXE build and hardware sensor readings must be validated on Windows.

## Keyboard shortcuts

- `Ctrl + F` — focus process search.
- `Ctrl + R` — refresh immediately.
- `Ctrl + E` — export CSV.
- Double-click a process — copy PID.

## Main files

- `FogMonitor.py` — desktop application.
- `Avvia-FogMonitor.bat` — launcher.
- `Diagnostica-FogMonitor.bat` — Python/Tkinter checks.
- `Build-EXE.bat` — builds the executable and ZIP.
- `assets/` — PNG, SVG and ICO branding.
- `tests/` — lightweight helper and translation tests.
- `.github/workflows/windows-release.yml` — automated Windows build and release.
- `CHANGELOG.md` — release history.

**Distribution note:** this ZIP is the publishable source package. An EXE is generated by running the build on Windows or by using GitHub Actions. Code signing can be added separately if you have an Authenticode certificate.

## Cloudflare Pages (website)

This repository includes a static public website under `public/`. In Cloudflare Pages, choose **Framework preset: None**, leave Root directory blank, set **Build command: `exit 0`** (or leave it blank for plain static HTML), and set **Build output directory: `public`**. No environment variables are required. Read [`CLOUDFLARE-PAGES.md`](CLOUDFLARE-PAGES.md) or visit `/CLOUDFLARE-PAGES.html` after deployment.

Cloudflare Pages publishes the website and source archive. The Windows desktop executable must be built separately on Windows or via GitHub Actions.
